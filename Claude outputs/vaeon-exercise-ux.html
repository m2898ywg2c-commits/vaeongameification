1 · The bug

A tap counts as a logged set even when there is no weight in it

When you tap a set row, the card fills in what it can and then checks whether the set is “filled” before writing it. That check passes if any field has a value. A rep count alone satisfies it.

So on a testing week, where there is deliberately no prescribed load, the rep count gets prefilled, the check passes, the row is written with a null weight, and the set is marked done. Four sets later the exercise closes. The keypad that would have let you type the weight never opens, because the code only opens it when nothing at all could be prefilled. 

app/plan/ExerciseCard.js

const filled = !!(next[i].weight || next[i].reps || next[i].secs
                  || next[i].text || next[i].km);
if (!filled) { setEditing(true); return; }

// should be: the measurement that DEFINES this kind must be present
const filled = kind === "weight" ? !!next[i].weight
             : kind === "reps"   ? !!next[i].reps
             : ...

There is a second, quieter one directly above it. The initial prefill honours calibrating and refuses to suggest a weight on a testing week. The tap handler does not, so a tap can write an app-derived number as though you had tested it. That is the feedback loop the September migration existed to kill.

And a third: the comment says the keypad should be open on a testing week, and the code says useState(false).

2 · The exercise card

One set at a time, with last week in reach

The current card shows every set at once as equal rows. That is a table, and a table is what you want afterwards, not during. Mid-session you are doing exactly one set, and the question is always the same: what am I lifting, and what did I do last time.

The change is to promote the live set and demote the rest. Same data, same writes, same per-set logging. The table is still there once the exercise is finished.

3 · The Engine Room

Your gym programmes time, not sets

Every board you sent is an AMRAP, an EMOM or a circuit. None of them is sets by reps by weight, which is the only shape the app can currently hold. An AMRAP has a cap and a score. An EMOM has an interval and a station. Forcing either into the exercise card is what makes conditioning feel bolted on.

The Engine Room is a second session type, with its own card. It sits alongside the strength days rather than inside them, and it scores rounds and reps instead of load.

4 · Three new sessions

Built from your gym’s own grammar

Your boards have a house style: an erg, a loaded carry or push, a wall ball or burpee, and a run. Thirteen to twenty minutes. These three keep that shape and point it at HYROX, so they sit next to Revolution’s sessions rather than competing with them.

Your gym’s four boards go in as fixed sessions alongside these, unmodified, the same way the HYROX simulation day already works: authored, not generated, and excluded from substitution.

5 · Before I build

Four things only you can answer

Does the Engine Room replace a strength day or sit on top?

You asked for more HYROX work in each day and a new section. Both is four hard days a week plus whatever you do at Revolution. I would make the Engine Room the bonus day and add one conditioning finisher to each strength day, not two full sessions.

Should I fix the logging bug now, separately?

It is three small changes and it is losing data every session you train. I would ship that on its own, today, rather than hold it behind this review.

Carlito across the whole app, or landing page only?

It currently stops at the landing page. Carrying it through means every screen in the app changes face, and the app was deliberately set in Inter for tabular figures at arm’s length. I would keep numbers in Inter and move only prose.

Meal planning for everyone: the flag, or the age gate too?

I will open the rollout flag. I am not touching the age check, which exists because calorie targets aimed at teenagers are a recognised risk factor. That stays whatever else changes.

Mark it up and tell me what is wrong. Nothing in this sheet exists in the repo yet.
